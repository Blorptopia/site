Preamble

This blog post is meant for you if you have tried to learn lifetimes using the Rust Book or Rustlings and gotten confused, or if you want to sanity-check that you really understood lifetimes.

What a lifetime is

Lifetimes are compile-time variables, similar to generics. They describe to the Rust compiler how long some data must be able to exist relative to some other data. Lifetimes consist of two parts: the definition and the usage, similar to how you define generics and then use them later. While you can name generics whatever you want, the convention is to use a single-letter lifetime name like 'a.

What a lifetime describes

In this example, we are defining a lifetime named 'a and using it both for the parameter and the return value. This states that the return value exists for at most as long as the parameter.

If we drop text, reference stops being usable and cannot be used anymore, making the example above fail to compile.

'static - the special case

While usually the name of a lifetime is just that - a name, 'static breaks that rule by introducing special behaviour whenever its name is used as a lifetime. The static lifetime marks data that can be used for as long as you wish.

Case 1 - &'static str

You can for example use &'static str to point to a string slice directly in the binary itself.

Case 2 - Generics

Imagine if we had a function that takes in any type that can be converted to a &str (using AsRef<str>). This would then support taking in both a &'static str, a &String and an owned String.

This works great for a function that takes in a reference and stops using it when the function returns. However, if you want to use the reference somewhere after the function has returned, this stops working.

This example doesn't compile, as you are sending text to another thread where Rust cannot guarantee how long it will be used for. If this constraint wasn't here, text could be dropped before it was printed, causing the program to print memory that could possibly have been reused for something else.

If, however, you add a 'static lifetime bound to text, this would work with the exception of calling the function with a reference to a locally owned string.

Here you also see the distinction between 'static and "lasts until the program exits", as you can pass in an owned string to a function requiring the 'static lifetime bound on a parameter.
