Preamble

This blogpost is meant for you if you have tried to learn lifetimes using the rust book or rustlings and gotten confused, or if you want to sanity check that you really understood lifetimes.

What a lifetime is

Lifetimes are compile time variables similarly to generics. They describe to the rust compiler how long some data must exist relative to some other data. Lifetimes consist of two parts - the definition and the usage, similar to how you define generics and then use them later. While you can name generics whatever you want, the convention is to use a single letter lifetime name like 'a.

What a lifetime describes

In this example we are defining a 'a lifetime and using it both for the parameter and the return value. This states that the return value exists for at least as long as the parameter.

If we drop text, reference stops being usable and cannot be used anymore, making the example above fail to compile.

'static - the special case

While usually the name of a lifetime is just that - a name, 'static breaks that rule by introducing special behaviour whenever it's name is used as an lifetime. The static lifetime marks that the data will never go out of scope.

Case 1 - &'static str

You can use &'static str to point to a string slice directly in the binary itself.

Case 2 - Generics

Imagine if we have a function that takes in any type that can be converted to a &str (using AsRef<str>). This would then support taking in both a &'static str, a &String and an owned String.

This works great for a function that takes in a reference and stops using it when the function returns. However if you want to store the reference somewhere after the function has returned, this stops working.

Here you also see the distinction between 'static and "lasts until the program exits", as you can pass in an owned string to a function requiring the 'static lifetime bound on a parameter.
